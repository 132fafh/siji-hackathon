# 思迹 · AI 提问澄清与想法留痕

> 先留痕，再澄清，后回答。AI 提供镜子和候选，人始终保留判断权。

「思迹」是一款 AI 提问澄清与想法留痕工具，服务经常使用 AI 辅助创作、研究或思考、但容易在长篇回答中丢失原始想法的人。它解决的不是"怎样更快生成答案"，而是：想法模糊时先保存原始表达、陷入混乱时只给低负担提示、由用户自己说出下一步、保留从混乱到明确问题的演化过程、允许空白与恢复。

## 运行方式

零构建、零依赖的纯前端应用（原生 HTML/CSS/JS）。

```bash
# 方式一：Python（任选端口）
cd siji
python -m http.server 8137
# 打开 http://localhost:8137/

# 方式二：Node
npx serve siji

# 方式三：直接双击 index.html（多数浏览器可用，推荐本地服务器方式）
```

## 已实现功能

- **首页 / 新思考**：单一突出输入框，"不用组织语言，直接写下来"；原话与时间戳保存后不可被 AI 覆盖。
- **澄清工作区**：
  - AI 简短复述（≤100 字，"这可能是在问……""我暂时理解为……"，明确标注推测，可随时纠正）；
  - 三张轻量提示卡（每次一个小动作：留住一个词 / 回到具体经验 / 寻找关系 / 找反例 / 回到最初目标……），支持换一组、自由补充、跳过澄清；
  - 每轮更新"当前暂定问题"：原文、补充原话、暂定问题、AI 推测部分分列，推测可否定，问题文本可直接改；
  - 最多主动 3 轮；每阶段都可否定、跳过、返回；确认后才生成回答；
  - 回答分四段：相对确定的事实 / 基于假设的解释（标注推测）/ 仍缺少的信息 / 可继续验证的方向；
  - 回答后可反馈（理解准确 / 有帮助 / 理解错了返回修改）。
- **想法空白**：明显的"我现在空白了"入口 → 四个低负担选项（暂停 / 只看三个关键词 / 回到原始表达 / 新方向），恢复时由用户判断"回来了 / 修改 / 新方向"。
- **思考路径**：纵向时间线，实线=用户原话，虚线=AI 推测（已标注），空白/否定/跳过/确认等事件原样保留。
- **历史记录**：查看、继续、重命名、删除（二次确认）、导出 Markdown。
- **详情与导出**：完整记录阅读视图 + 下载 / 复制 Markdown。
- **设置**：AI 模式切换、API 配置、测试连接、导出 JSON 备份、一键删除全部本地数据。
- 数据保存在当前浏览器 localStorage；移动端 / 桌面端响应式；键盘可达、焦点可见、尊重减少动态偏好。

## AI 服务配置

AI 调用封装在 `js/ai-service.js`（接口：`restate / hints / draft / answer`），可在设置页切换：

- **演示模式（默认）**：`js/demo-ai.js` 本地规则生成，无需密钥；所有 AI 内容标注「演示模式」，不伪装真实 AI 能力。API 失败时自动回退到此模式，流程不中断。
- **API 模式**：OpenAI 兼容接口（`/chat/completions`）。在 设置 → API 模式 填写：
  - API 端点（如 `https://api.openai.com/v1`）
  - 模型（如 `gpt-4o-mini`）
  - API 密钥（仅保存在本机浏览器 localStorage，不会写入代码或上传）
  - 点"测试连接"验证。系统提示词完整内置了行为准则（不诊断、不测 IQ、不贴标签、可纠正措辞、标注推测等）。

接入新 AI 供应商：只需替换 `js/ai-service.js` 中 `api` 对象的四个方法，视图层无需改动。

**安全提示**：浏览器直连第三方 API 意味着密钥对该端点可见；生产环境应改为后端代理。接入云端后，一次思考仅在对应环节发送必要文本（原始表达 + 已有澄清过程），详见设置页说明。

## 演示模式说明

演示模式是**规则模板**，不是真 AI：
- 复述/暂定问题由关键词提取 + 固定句式拼合；
- 回答四段为保守模板（事实引用原话，假设明确标注为推测）；
- 界面全局徽标与回答页提示条均标注「演示模式」；
- 用途：在无密钥时验证完整交互流程与数据结构。请勿把其输出当作真实 AI 能力。

## 测试

```bash
node test/run-tests.js
```

45 项断言，覆盖：数据层（原始表达不可变、增删改查、持久化）、演示 AI 行为约束（复述 ≤100 字、可纠正措辞、推测标注、三张提示、四段回答、跳过轮次不计入）、完整流程模拟（三轮澄清 → 空白 → 恢复 → 确认 → 回答 → 反馈返回修改）、Markdown 导出结构。

## 隐私

- 历史记录仅保存在当前浏览器 localStorage，不默认上传；
- 支持一键删除全部本地数据（设置页）与 JSON 全量导出备份；
- API 密钥仅存本机；不建立用户画像，不诊断心理状态，不测量 IQ，不判断固定思维类型。

## 扩展交接与本地演示服务

在 `siji-hackathon` 项目根目录运行 `node server/server.js`，然后：

1. 打开 `http://localhost:8141/mock-kimi.html`，加载项目扩展。
2. 在模拟页输入草稿并停顿，等待扩展提示，点击「进入思迹」。
3. 扩展打开 `http://localhost:8141/#/plugin` 并注入 `bridge/siji-bridge.js`。桥接脚本读取并立即删除 `chrome.storage.local.sijiHandoff`，保存草稿后跳转到对应工作区；没有草稿时进入 `#/new` 并轻提示。
4. 桥接脚本只由扩展注入，`index.html` 中仅有说明注释，普通浏览器无需加载 `chrome` API。一次性载荷和页面状态锁用于避免重复接收、重复创建。
5. 草稿只写入本地会话，原文不进入 URL。近期用户消息作为辅助上下文单独展示，不覆盖原始表达。

服务端当前**未配置真实 AI**，API 输出全部标注为 demo。`recall` 的 0–100 分仅表示中文二字片段与英文词的重叠程度，**不是真实遗忘概率**；无原文匹配时不生成证据或新增内容。接口与错误格式详见 `server/README.md`。
