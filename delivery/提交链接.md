```bash
cd D:\Kimi\siji-hackathon

```

打开 `http://localhost:8141/`。插件模拟页为 `/mock-kimi.html`，扩展加载目录为 `extension/`。历史记录保存在当前浏览器 localStorage，刷新后仍保留；公开 DeliData 案例只读，不写入个人历史。

## AI 服务与演示边界

- 默认无需 API Key，不宣称真实遗忘检测、读心、高精度个性化或所有 AI 网站均已实测兼容。
- 主流程的默认规则演示在浏览器内生成；星落扩展调用本站 Cloudflare Worker 的规则接口。公开部署未配置真实模型密钥，不会向第三方真实模型服务发送这些内容。
- 真实 AI 使用可替换的服务模块。推荐仅在服务端设置 `SIJI_API_BASE / SIJI_API_KEY / SIJI_MODEL / SIJI_TIMEOUT_MS`，详见 `server/README.md`，密钥不得提交到仓库。
- 设置页保留的自定义 API 浏览器直连是早期实验路径，不是公开部署所需，也不建议在公共设备中填写密钥；生产使用应统一改为服务端配置。
- 原始表达不可被 AI 覆盖；AI 候选、推测与用户原话分开保存和展示。用户可否定、跳过、返回、暂停或离开。

## 修复后如何更新同一网址

已提交的 `https://siji-hackathon.pages.dev/` 不需要更换：

```bash
node tools/build-cloudflare.js
powershell -ExecutionPolicy Bypass -File tools/package-cloudflare.ps1
```

在 Cloudflare 的 `siji-hackathon` 项目中选择 **Create deployment → Production**，上传 `tools/cloudflare-pages.zip`。构建脚本使用 `npx esbuild` 生成 `_worker.js`，API 与本地 Node 服务共用 `server/api-core.js`。GitHub 源码可另行提交更新；Bilibili 视频内容若需替换，则应重新发布或更新视频链接。

## 后续最值得验证的三个产品假设

1. **低负担澄清能帮助用户留住并继续说清原始想法。** 用同一批真实任务比较自由书写与“三张轻量提示卡”，观察原话保留率、用户主动补充率和放弃率，而不是用 AI 分数代替人的判断。
2. **行为与上下文结合比单纯停顿更能识别需要回忆辅助的时机。** 采集经用户明确许可的标注数据，与“仅停顿”基线比较误报率、召回率和实际恢复率；现有分数只作演示，不冒充经过验证的遗忘概率。
3. **可调边界扩张总率能在探索与可读性之间取得更好的平衡。** 比较不同上限下的候选接受率、重复拦截率、阅读完成度和主观负担，验证用户控制是否优于固定无限扩展。
